# 股迹 v0.6 · 运行说明

> 版本：v0.6（2026-11-05，v0.5.1 基础上新增人机交互四件套；v0.5 见 `versions/v0.5/`，v0.5.1 见 `versions/v0.5.1/`）
> 定位：实时行情 + 持仓盈亏 + 分时 + 日/周/月 K 线 + 常用技术指标 + 追踪信号 + 池子总览 + 指数闸门 + 组合风险 + 预测回测 + 日K历史回放 + 信号卡存图的本地看板。
> 数据来源：腾讯证券公开行情接口。仅供课程学习，不构成投资建议。

---

## 1. 运行环境

- Windows 10/11；
- Chrome 或 Edge（推荐最新版）；
- 实时行情、分时和历史日线需要联网；
- 可选：Python 3（启动本地服务器、更新快照；不需要安装第三方包）。

程序本身是纯静态网页，不需要 npm、不需要后端、不需要 API Key，也没有引入任何第三方图表库。

---

## 2. 启动方法

### 方法 A：双击 `start.bat`（推荐）

1. 双击 `start.bat`；
2. 启动器先自动增量更新快照（联网时一般 10–30 秒；断网或接口不可用时自动跳过，继续用现有快照启动，页面顶部会显示实际数据日期）；
3. 随后弹出一个“股迹本地服务器”命令行窗口，并自动打开浏览器；
4. 地址是 `http://localhost:8000/index.html`；
5. 关闭那个命令行窗口即停止本地服务器。

如果 8000 端口被占用，在项目目录手动执行 `python -m http.server 8080`，再打开 `http://localhost:8080/index.html`。

### 方法 B：直接双击 `index.html`

腾讯行情接口返回 `Access-Control-Allow-Origin: *`，从 `file://` 打开通常也能取到行情。部分浏览器限制较严时改用方法 A。

## 3. 页面操作

### 3.1 行情、分组与持仓

1. **自选分组**：“自选行情”右上角可在“课程演示组”（10 只白马 + 2 个指数）和“实战观察组”（10 只股票 + 2 只 ETF + 4 个指数）之间切换，选择记在 `localStorage` 的 `guji.pool.group`。
   - 分组清单只维护 `js/data/pool.json` 一处；改完后运行 `python tools/build_universe.py`，页面与采集脚本都会跟随。
   - 切换分组后，另一组的持仓仍会继续取价并计入合计，不会因为不在当前自选里变成“--”。
2. **自选行情**：当前分组每 3 秒批量刷新，显示最新价、涨跌幅、涨跌额、量比、换手率、最高/最低。刷新采用增量更新，只改数字，不重建整张表。
3. **数据截至**：顶部固定显示“数据截至 YYYY-MM-DD”。如果距最后一个交易日已经过去 2 个或更多交易日，会出现黄色横幅，提示双击 `start.bat` 自动更新，或手动运行 `python tools/build_snapshot.py --update`。
4. **建仓**：右侧表单默认是“建仓”，选择一只尚未持有的股票，填股数和成本价。股数必须是正整数，成本价必须大于 0；已持仓会提示改用“加仓”或“修正”。
5. **加仓**：在持仓行点“加仓”，输入新增股数和本次成本价，按加权平均合并成本。例如 100 股 @1500 加 100 股 @1300，合并为 200 股 @1400。
6. **减仓**：每股成本保持不变；减到 0 会弹窗确认并清仓。减仓不计算已实现盈亏。
7. **修正 / 删除**：修正只纠正录入错误；删除直接移除整条持仓。
8. **合计**：总市值、总成本、浮动盈亏、今日盈亏、权重随行情刷新；金额以“分”为单位计算，避免浮点误差。

### 3.2 图表：分时 / 日K / 周K / 月K

9. **分时**：优先请求腾讯分时接口；接口不可用时用本次页面打开后累积的 3 秒采样点兜底。快照模式下分时图暂停。
10. **K 线周期**：日线来自快照，周线按 ISO 周、月线按自然月由日线聚合；`open` 取第一根、`close` 取最后一根、`high/low` 取极值、`volume` 求和；最后一根未走完的周/月标“未走完”。
11. **指标面板**：三档预设——
    - 简洁：MA20、MA40 + 成交量；
    - 标准：MA5/10/20/40 + 成交量 + MACD；
    - 完整：当前周期全部可用均线 + BOLL + 成交量 + MACD。
12. **自定义指标**：
    - 日K提供 MA5/10/20/30/40/60/120/250，其中 MA20/60/120/250 标注“月线/季线/半年线/年线”；周/月提供到 MA120；
    - 样本不足的均线自动禁用；切换周期时面板同步刷新，周/月不会残留 MA250；
    - BOLL(20,2) 可单独开关；副图最多同时选 2 个（成交量、MACD、KDJ、RSI）；
    - 月K默认对数坐标；指标选择按周期保存在 `guji.chart.prefs.v1`。
13. **十字光标**：鼠标移到 K 线上显示开高低收、涨跌幅、成交量、均线和副图值；移动端用手指按住查看。

### 3.3 分析工作台

分析工作台有 5 个页签：追踪信号、池子总览、指数闸门、组合风险、预测与回测。

14. **追踪信号**：对当前选中股票按日/周/月线计算 10 张规则卡：
    - 均线排列（MA5/10/20/60：多头排列 / 空头排列 / 纠缠）；
    - 收盘价相对 MA40 的偏离；
    - 距年线（MA250）的偏离；周/月显示“距 MA250（周线/月线）”，不把 250 周误读为一年；
    - MACD 金叉/死叉/多头/空头与红绿柱变化；|DIF−DEA| 不足收盘价 0.02% 时加“临界”提示；
    - KDJ、RSI、BOLL、20 日动量、20 日年化波动、距 20 日高/低点。
    摘要句由规则拼接，明确标注“规则生成，仅供课程学习”。
15. **观察池**：对当前分组用固定权重打分（20 日动量 18、趋势 15、MACD 8、量能 5、低波动 -8），取前 5 名。页面写“观察池”，不写“推荐”。
16. **池子总览**：把当前分组所有标的排成一张表——
    - 名称、收盘、当日涨跌、近 20 日涨跌、相对沪深 300 的相对强度、均线排列、MACD 状态、是否站上 MA20、距 20 日高点、信号摘要；
    - 按当日涨跌幅降序，同一天逆势走强的集群会排在一起；
    - MACD 金叉行高亮；相对强度 = 个股 20 日涨幅 − 沪深 300 同期涨幅，日期对不齐时显示“--”；
    - 表格基于日线收盘，不随盘中 3 秒行情跳动。
17. **指数闸门**：创业板指与科创 50 各一张卡——
    - 收盘价与当日涨跌、距年线（MA250）百分比、MA20 上下方、DIF/DEA 与金叉/死叉状态；
    - DIF 连续拐头向上天数（≥3 天 = 一级闸门“企稳萌芽”达成）；
    - 收盘是否收复 MA20（= 二级闸门“买点解锁”）；
    - 近 20 日涨跌幅。两层闸门同时满足才显示“买点解锁”。
18. **组合风险**：第一大权重、等效持股数（1/HHI）、20/60/250 日年化波动、60 日最大回撤、相对沪深 300 的 60 日 β 与相关系数、有效样本天数。假设权重不变、每日再平衡、无现金/手续费。
19. **预测与回测**：Holt 对数收盘价 5 日预测 + 80% 区间；逻辑回归 7 特征次日上涨概率；walk-forward 按时间顺序滚动训练，输出命中率、基准、AUC、精确率/召回率、Holt MAE 与朴素基线。跑输基准时如实显示。

### 3.4 告警、快照与存储

20. **盘中告警**：实时行情触发四类规则——
    - 涨跌幅绝对值达到 3%；
    - 量比达到 2；
    - 价格上穿/下破 20 日均线，或创 20 日新高/新低；
    - MACD 金叉/死叉：用最近 250 根日线计算 DIF/DEA（只喂 60 根时 EMA 未收敛，会把临界状态判成金叉、也会把交叉日期挪后一天），取最后 2 根已完成日 K，昨日在下、今日在上为金叉，反之为死叉；日线不足 60 根不判。
    - MACD 临界：|DIF−DEA| 不到收盘价 0.02% 时，在告警 detail 补“（DIF−DEA≈0，临界，多空状态在复权口径间会翻转，以收盘多源复核为准）”；追踪信号的 MACD 卡也会标“DIF−DEA≈0 临界”。

    告警覆盖当前分组与全部持仓（另一分组的持仓也会盯），指数不产生告警。

    涨跌幅、量比、价格位置同一股票 + 同一规则 30 分钟内只提醒一次；MACD 交叉是日 K 级状态变化，冷却 20 小时，一根日 K 只报一次。告警流最多保留 50 条。
21. **快照兜底**：连续 3 次行情请求失败后自动切换内置日线快照，顶部显示“快照模式”和快照时间；之后按 3/6/12/30 秒退避重试。
22. **本地持仓恢复**：持仓保存在 `guji.holdings.v2`。非法 JSON 会把原文备份到 `guji.holdings.corrupt.<时间戳>`，恢复示例持仓并显示黄色提示；旧版 `guji.holdings.v1` 自动迁移。
23. **自检页**：打开 `tests.html`，应显示“110 / 110 通过”。纯函数断言，不发起行情请求。

## 4. v0.5 → v0.6 新增：动效、回放、存图、自动更新与人机交互

24. **数字滚动与涨跌闪烁**：指数卡、自选表、持仓表、汇总卡与图表摘要的数字在行情刷新时平滑滚动到新值，发生变化的单元格按 A 股惯例闪红（涨）或闪绿（跌）后自动还原。
25. **图表入场动效**：切换标的或周期时，K 线逐根从基线"生长"、均线与副图指标从左向右描出，分时线逐段描绘；3 秒例行刷新不会重播动画，鼠标悬停会立即跳到完整帧。

### 指标口径

| 指标 | 口径 |
| --- | --- |
| MA | 简单移动平均，样本不足返回 `null`，不拿 0 顶替 |
| EMA | `α = 2/(n+1)`，第一个有效值作为种子 |
| MACD | `DIF = EMA12 − EMA26`，`DEA = EMA9(DIF)`，柱 `= 2 × (DIF − DEA)` |
| KDJ | `RSV = (C − L9)/(H9 − L9) × 100`，`K = 2/3·K_prev + 1/3·RSV`，`D = 2/3·D_prev + 1/3·K`，`J = 3K − 2D`，种子 50 |
| RSI | Wilder 平滑，6/12/24；全平盘记 50，全上涨记 100 |
| BOLL | MA20 ± 2 × 总体标准差；标准差为 0 时三轨重合 |
| 年化波动 | 日收益样本标准差 × √252 |
| 最大回撤 | 区间内峰值到后续谷底的最大跌幅 |
| 相对强度 | 个股近 20 根日线涨幅 − 沪深 300 同首尾日期涨幅 |

### MACD 口径复核（2026-10-31 修正）

- 判交叉的回看窗口从 60 根改为 250 根（`MACD_LOOKBACK`），60 根仅作最低样本门槛；250 根与全量历史算出的 DIF/DEA 已对齐。
- 2026-10-30 收盘：250 根窗口下只有华东医药金叉（DIF -0.167 / DEA -0.174，gap 0.0245%）。
- 丽珠集团 DIF 0.1249 / DEA 0.1253，`|DIF−DEA|/收盘 = 0.0012%`，低于 0.02%，信号卡标“临界”，不产生金叉告警；60 根窗口会把它误判为金叉。
- 德业股份的金叉发生在 2026-10-29（当日 DIF 已上穿 DEA）；60 根窗口因 EMA 未收敛把交叉挪到 10-30。要复盘 10-29 需用当日快照重跑，不能用 10-30 的最后一根反推。

### 边界与已知问题

- 技术指标按常见公式自行实现，不保证与任何行情软件的数值逐位一致；
- 相对强度要求个股与沪深 300 在首尾日期都有收盘价，停牌或日期缺失时显示“--”；
- 指数闸门只按收盘价判断，不包含成交量、北向资金、政策事件等条件；
- 预测模型很弱：茅台当前样本外方向命中率 51.3%，低于“总是猜多数类”的 53.8% 基准，AUC 0.489 接近随机；页面如实展示；
- 组合风险假设权重不变、每日再平衡，未计现金、手续费、税费和停牌；
- 减仓不计算已实现盈亏、手续费和税费，也没有按批次（FIFO）记成本；
- 告警是规则引擎，不是机器学习；告警不写入 localStorage，刷新页面后清空；
- 快照不会随页面自动更新（v0.5.1 起 `start.bat` 启动时会自动增量更新，`file://` 直开仍需手动 `--update`）；页面会在过期 2 个交易日后提示；
- 页面关闭后不再盯盘，不是 7×24 服务；
- 长鑫科技 2026-07-27 上市，只有 64 根日线，MA250 与预测回测不可用，页面显示“--”；
- 浪潮信息 2015-01-20 至 2015-02-05 没有日线：公司因重大事项停牌、2015-02-06 复牌；腾讯原始接口同样没有这段，不是采集遗漏。

## 6. 数据来源与合规

- 实时报价、分时、历史日线均来自腾讯证券公开接口；
- 股票使用前复权日线；ETF 与指数不复权；成交量单位为手；
- 快照覆盖 2015-01-01 至 2026-11-04，22 只股票/ETF + 4 个指数；
- 前复权价可能出现 0 或负值（累计分红导致），这些 bar 在读取时被剔除，并在界面标注数量；
- 程序不接入券商、不执行交易、不上传持仓，不包含账号密码；
- 页面固定显示“仅供课程学习，不构成投资建议”。

## 9. 常见问题

**K 线区域空白**
- 确认已点“日K/周K/月K”，分时页签下不显示 K 线；
- 打开 Console 看是否有脚本报错；
- 快照约 3 MB，首次加载会比 v0.3 慢一点。

**切换分组后表格空了几秒**
- 页面会先用快照补上新标的，再等 3 秒实时行情；如果一直为空，看 Console 与 Network。

**“数据截至”是旧日期 / 出现黄色横幅**
- 双击 `start.bat` 重新启动即可自动增量更新（v0.5.1 起）；或手动运行 `python tools/build_snapshot.py --update`，完成后刷新页面；
- 增量模式会多取 10 天重叠数据核对复权价；如果腾讯因分红重算了历史前复权价，脚本会自动全量重采。

**池子总览里某只股票显示“--”**
- 该标的上市时间太短（如长鑫科技只有 64 根），MA250、相对强度或 20 日指标可能样本不足；
- 这是数据边界，不是渲染错误。

**指数闸门显示“日线不足”**
- 快照里没有该指数，先运行一次 `--update`；实战观察组才包含创业板指与科创 50。

**预测按钮提示“至少需要 250 根日线”**
- 该股票快照样本不足，无法做 walk-forward；换一只上市更早的股票再试。

**行情一直显示“--”**
- 检查网络；打开开发者工具 Console/Network 看请求是否失败；
- 腾讯接口可能临时限制访问，等一会儿点“刷新”，或直接看快照模式。

**持仓刷新后没了**
- 检查浏览器是否禁用了 localStorage；换浏览器/清缓存会丢失，本项目没有云端同步；
- 如果看到“本地持仓数据损坏”，按提示到 `guji.holdings.corrupt.*` 备份键找原文。

**端口被占用**
- 手动执行 `python -m http.server 8080`，改用 8080。

## 10. 更新快照与分组

### 9.1 只换池子

1. 编辑 `js/data/pool.json`（代码、名称、腾讯代码、类型、行业）；
2. 运行：

```bat
python tools/build_universe.py
```

3. 刷新页面。`build_universe.py --check` 可以检查 `universe.js` 是否与 `pool.json` 一致。

### 9.2 更新日线

```bat
python tools/build_snapshot.py --update
```

- 已有标的只补最后一个日期之后的数据；新标的从上市日开始全量采集；
- 增量会多取约 10 天重叠数据；若重叠区收盘价明显变化（前复权因子重算），自动改为全量；
- 需要系统 `curl`（Windows 10/11 自带）；
- 如果 `web.ifzq.gtimg.cn` 被腾讯 WAF 拦截（返回 HTML/501），脚本会自动改用 `proxy.finance.qq.com` 或 `ifzq.gtimg.cn` 的同一接口；
- 采集不完整时只写 `snapshot.partial.js`，不会覆盖正在使用的 `snapshot.js`。

强制全量：

```bat
python tools/build_snapshot.py --update --full
```
