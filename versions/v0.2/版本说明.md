# v0.2 版本说明

- 日期：2026-10-30
- 状态：可运行的第二个版本，已完成 v0.1 发现问题的修复，并加入分时图与基础告警
- 运行：双击 `start.bat`，或 `python -m http.server 8000` 后打开 `index.html`
- 自检：`tests.html` 40 / 40 通过

## 一句话目标

让页面在 3 秒刷新下不打断用户操作，让本地数据损坏后可恢复且可见，让用户能看到单只股票的分时走势和基础异动告警。

## 已完成

### 1. 增量渲染

- 行情表、持仓表、汇总卡、指数卡首次创建节点，后续只更新变化的文本和 class；
- 不再在刷新路径对 `tbody` 赋 `innerHTML`；
- 4.2 秒刷新后，同一个 `<tr>`、同一个按钮仍在，按钮焦点不丢失；
- 选中“五粮液”文字后刷新 4.2 秒，文本选择仍保留。

### 2. localStorage v2

- 新键：`guji.holdings.v2`，结构为 `{version:2, holdings:[...]}`；
- 兼容旧版 `guji.holdings.v1` 数组并自动迁移；
- 非法 JSON / 结构不可识别时：
  - 原文备份到 `guji.holdings.corrupt.<时间戳>`；
  - 恢复示例持仓；
  - 顶部显示提示，包含备份键名；
- 空持仓数组 `{version:2,holdings:[]}` 不会被误判为损坏；
- 保存成功/失败有表单反馈。

### 3. 请求正确性与退避

- 每次批量行情请求有递增 `requestId`，旧响应不能覆盖新响应；
- 缺失标的的对应行显示 `--`，不再沿用旧价格；
- 连续失败按 3/6/12/30 秒退避；
- 第 3 次失败切快照模式，恢复后回到实时；
- 顶部时间优先使用腾讯行情返回时间，不再用 `Date.now()` 冒充行情时间；
- 行情缺失/失败时显示明确提示，快照模式与实时模式文案分开；
- 快照状态下继续失败时，横幅明确写“继续使用 10/29 15:00 快照”，不再与“快照模式”徽章冲突（来自本人真实 DevTools Offline 截图 R13）。

### 4. 表单与空状态

- 字段级错误 + 顶部错误汇总；
- 错误时聚焦第一个有问题的字段；
- 添加/编辑/删除/清空/载入示例均有成功或失败提示；
- 空持仓显示“还没有持仓”，汇总显示 `--`；
- 空告警、无分时数据分别有空状态。

### 5. 分时图

- 自选股下拉或点击行情行切换；
- 腾讯分时接口优先，过滤午休，保留 09:30—15:00；
- 接口失败时使用本页 3 秒采样兜底，并明确显示“本页采样”；
- 快照模式下分时图暂停，避免 10/30 分时与 10/29 快照价混用；
- Canvas 绘制，无第三方图表库。

### 6. 基础告警

- 涨跌幅绝对值达到 3%；
- 量比达到 2；
- 上穿/下破 20 日均线、创 20 日新高/新低；
- 同一股票 + 同一规则 30 分钟冷却；
- 告警流最多 50 条，清空后不会立刻被旧事件刷回；
- 快照/离线状态不产生新告警。

## 已知问题

1. 告警只存在内存，刷新页面后清空；
2. 交易状态未处理法定节假日；
3. 分时接口失败时只能使用本次打开页面后的采样，不能补历史分钟；
4. 真实 DevTools Offline 已由本人补测（R13），但修复后的快照文案分支由 AI 模拟验证（R14），还没在真实断网下再拍一张；
5. 表单默认股票可能已在持仓中，直接提交会触发“该股票已在持仓中”；这是校验生效，但默认选中可再优化；
6. 告警规则是固定阈值，不是自适应模型；z-score 延后到 v0.3。
