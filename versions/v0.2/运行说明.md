# 股迹 v0.2 · 运行说明

> 版本：v0.2（2026-10-30）
> 定位：实时行情 + 持仓盈亏 + 分时观察 + 基础告警的本地看板，是后续 AI 分析/预测/观察池的数据底座。
> 数据来源：腾讯证券公开行情接口。仅供课程学习，不构成投资建议。

---

## 1. 运行环境

- Windows 10/11；
- Chrome 或 Edge（推荐最新版）；
- 实时行情和分时数据需要联网；
- 可选：Python 3（只用于启动本地静态服务器，不需要安装任何第三方包）。

程序本身是纯静态网页，不需要 npm、不需要后端、不需要 API Key。

---

## 2. 启动方法

### 方法 A：双击 `start.bat`（推荐）

1. 双击 `start.bat`；
2. 会弹出一个“股迹本地服务器”命令行窗口，并自动打开浏览器；
3. 地址是 `http://localhost:8000/index.html`；
4. 关闭那个命令行窗口即停止本地服务器。

如果 8000 端口被占用，命令行窗口会提示错误。此时可以在项目目录手动执行：

```bat
python -m http.server 8080
```

然后浏览器打开 `http://localhost:8080/index.html`。

### 方法 B：直接双击 `index.html`

腾讯行情接口返回 `Access-Control-Allow-Origin: *`，所以从 `file://` 打开通常也能取到行情。部分浏览器对本地文件限制较严，如果行情不刷新，改用方法 A。

### 方法 C：手动启动

在项目目录执行：

```bat
python -m http.server 8000
```

浏览器打开 `http://localhost:8000/index.html`。

## 3. 页面操作

1. **自选行情**：10 只股票每 3 秒批量刷新，显示最新价、涨跌幅、涨跌额、量比、换手率、最高/最低。刷新采用增量更新，只改变化的数字，不重建整张表。
2. **分时观察**：在“分时观察”下拉框选择股票，或点击自选行情中的行，查看当日分时图。优先请求腾讯分时接口；接口不可用时，用本次页面打开后累积的 3 秒采样点兜底。
3. **添加持仓**：在右侧表单选择股票、填股数和成本价，点“添加持仓”。股数必须是正整数，成本价必须大于 0；同一只股票不能重复添加。错误会在字段下方和表单顶部同时提示。
4. **编辑/删除**：在“我的持仓”表格右侧点“编辑”或“删除”。编辑时表单会切换到“保存修改”，可点“取消编辑”退出。
5. **合计**：总市值、总成本、浮动盈亏、今日盈亏、权重都会随行情刷新；金额以“分”为单位计算，避免浮点误差。
6. **盘中告警**：实时行情触发三类基础规则——
   - 涨跌幅绝对值达到 3%；
   - 量比达到 2；
   - 价格上穿/下破 20 日均线，或创 20 日新高/新低。

   同一股票 + 同一规则 30 分钟内只提醒一次；告警流最多保留 50 条。快照/离线状态不产生新告警。
7. **快照兜底**：连续 3 次行情请求失败后自动切换内置的 2022—2026 前复权日线快照，顶部显示“快照模式”和快照时间；之后按 3/6/12/30 秒退避重试。快照模式下分时图暂停，避免把实时分时和快照价格混在一起；如果页面加载时就已离线，也会明确提示“继续使用某日某时快照”。
8. **本地持仓恢复**：持仓保存在 `localStorage` 的 `guji.holdings.v2`。如果该键被手动改成非法 JSON，页面会：
   - 把原文备份到 `guji.holdings.corrupt.<时间戳>`；
   - 恢复示例持仓；
   - 显示黄色提示，说明备份键名；
   - 旧版 `guji.holdings.v1` 数组会自动迁移。
9. **清空/示例**：右上角“载入示例”会替换当前持仓；“清空”会删除全部持仓。
10. **自检页**：打开 `tests.html`，应显示“40 / 40 通过”。这是纯函数断言，不发起行情请求。

## 4. v0.2 已完成与边界

已完成：

- 增量渲染：行情表、持仓表、汇总卡和指数卡不再每 3 秒整表重绘；
- 请求序号与旧响应保护：旧请求不会覆盖新请求；
- 缺失行情：对应行显示 `--`，不把旧价格继续标成实时；
- 3/6/12/30 秒退避；
- 行情时间优先使用接口返回的北京时间，而不是本机 `Date.now()`；
- localStorage v2：结构校验、旧版迁移、损坏备份、可见提示；
- 表单错误汇总、字段错误、保存成功/失败反馈；
- 分时图：腾讯分时 + 本页采样兜底 + 快照模式暂停；
- 基础告警：三类规则 + 30 分钟冷却 + 告警流；
- 自检从 23 条扩展到 40 条。

边界：

- 告警是规则引擎，不是机器学习；后续 v0.3 才做 z-score、组合分析和预测；
- 告警不写入 localStorage，刷新页面后清空；
- 分时图依赖腾讯分时接口；接口失败时只有页面打开后的采样，不补历史分钟；
- 交易状态只按北京时间判断周一至周五的 9:30—11:30、13:00—15:00，不处理法定节假日；
- 快照数据截至采集日（见 `js/data/snapshot.js` 的 `meta.fetchedAt`），之后不会自动更新；
- 页面关闭后不再盯盘，不是 7×24 服务。

## 8. 常见问题

**行情一直显示“--”**
- 检查网络；打开开发者工具 Console/Network 看请求是否失败；
- 腾讯接口可能临时限制访问，等一会儿点“刷新”，或直接看快照模式；
- 确认系统时间正确（交易状态按本机时间换算北京时间）。

**分时图提示“本页采样”或“暂无数据”**
- 说明腾讯分时接口暂时不可用；页面打开后每 3 秒的行情采样会继续补充；
- 快照模式下分时图会主动暂停，这是为了避免混用不同交易日的价格。

**持仓刷新后没了**
- 检查浏览器是否禁用了 localStorage；
- 换浏览器/清缓存会丢失，本项目没有云端同步；
- 如果看到“本地持仓数据损坏”，按提示到 `guji.holdings.corrupt.*` 备份键找原文。

**页面打开是空白**
- 确认脚本没有被浏览器插件拦截；
- 用 `start.bat` 的 localhost 方式打开；
- 打开 Console 看是否有报错，并截图记录。

**端口被占用**
- 手动执行 `python -m http.server 8080`，改用 8080。

## 9. 重新采集快照

```bat
python tools/build_snapshot.py
```

脚本会从腾讯证券接口按结束日期向前翻页，采集 2022-01-01 至今的日线，写入 `js/data/snapshot.js`。需要系统 `curl`（Windows 10/11 自带）。采集完成后刷新页面即可使用新快照。
