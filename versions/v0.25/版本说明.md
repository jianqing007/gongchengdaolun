# v0.25 版本说明

- 日期：2026-10-30
- 状态：v0.2 的持仓操作迭代版，解决“已持仓股票不能直接加仓”的可用性问题
- 运行：双击 `start.bat`，或 `python -m http.server 8000` 后打开 `index.html`
- 自检：`tests.html` 47 / 47 通过

## 一句话目标

把“添加持仓 / 编辑”改成更贴近真实持仓的 **建仓 / 加仓 / 减仓 / 修正** 四种动作，同一只股票始终只有一条持仓。

## 为什么这样改

- 旧行为：同一股票再次添加会被判为重复；用户只能删除再新增，或者到“编辑”里自己算新的总股数和平均成本；
- 不直接放开重复：同一只股票出现两行会让权重、总成本和盈亏重复计算；
- 交易动作与数据修正分开：加仓、减仓是交易；修正是纠正录入错误，语义不同。

## 本次实现

### 建仓

- 侧边表单默认“建仓”；
- 默认选中第一只尚未持仓的股票，减少误触重复；
- 如果选择的股票已持仓，提示“该股票已持仓，请用‘加仓’或‘修正’”，不会新增第二行。

### 加仓

- 持仓行增加“加仓”按钮；
- 输入“新增股数”和“本次成本价”；
- 按加权平均合并：

```text
新成本 = (原股数 × 原成本 + 新增股数 × 本次成本) / 总股数
```

- 例：100 股 @1500 + 100 股 @1400 → 200 股 @1450；
- 成功提示包含新增股数和新成本。

### 减仓

- 持仓行增加“减仓”按钮；
- 只输入减持股数，成本价字段隐藏；
- 每股成本保持不变；减到 0 时弹窗确认并清仓；
- 当前不计算已实现盈亏、手续费和税费，也不做 FIFO 批次成本。

### 修正

- 原“编辑”改名为“修正”，只用于纠正录入错误；
- 可改股数和成本价，但不会按加仓/减仓计算；
- 和日常交易动作分开，减少误操作。

### 其他

- 自选行情中已持仓按钮显示“加仓”，未持仓显示“+ 建仓”；
- 持仓表操作变为：加仓 / 减仓 / 修正 / 删除；
- 金额仍以“分”为整数基础计算，加权平均后的总成本按分求和；
- 行情、分时、告警、存储 v2 逻辑保持 v0.2 的行为。

## 本次实测

环境：本地 `http://127.0.0.1:8000`，ZCode 内置浏览器，1280×720 桌面和 390×844 移动端。

| 项目 | 结果 |
| --- | --- |
| 自检 | 47 / 47 通过 |
| 建仓 | 五粮液 100 股 @74.70，市值 ¥7,470、日盈亏 +¥242、权重 3.9% |
| 加仓 | 100@1500 + 100@1400 → 200@1450；总成本 ¥290,000 |
| 减仓 | 200@1450 减 50 → 150@1450，成本不变 |
| 减仓边界 | 减 999 股被拒绝，提示不能超过现有 150 股 |
| 修正 | 改为 160 股 @1440，行和 localStorage 同步 |
| 清仓 | 减仓全部股数，确认后删除该行 |
| 重复建仓 | 提示“该股票已持仓，请用‘加仓’或‘修正’”，行数不变 |
| 移动端 | 390×844 下页面无横向溢出，持仓表内部横向滚动 |

## 已知问题

1. 减仓不计算已实现盈亏、手续费和税费，也没有交易流水；
2. 加仓使用加权平均成本，不是 FIFO/分批成本；
3. v0.2 的边界仍在：告警不持久化、未处理法定节假日、分时接口失败时只能本页采样、快照模式分时暂停；
4. 真实交易时段的加仓/减仓和 R4 采样兜底仍需本人补测。
